## 一、先看结论

1. 在共同有限整数契约下，两份实现通过了人工期望和独立参考模型检查；这是实验范围内的证据，不代表已与生产所有订单类型、精度及重试接口等价。
2. 本次三个负载的 C++ 吞吐中位数更高，Java 的 p50 均更低。扫单 p99 近似，重复请求负载的 Java p99 更低。指标不是单一语言排名。
3. 不能用这些内存方法指标与当前 HTTP → 数据库 → 资金交割数据计算加速倍数。数据库基线在本次合同下**未测量**。
4. 尚未实现独立引擎的持久化、资金协议、影子流量、故障接管和状态迁移；它们在专项手册中是待验收方案，不是已上线能力。

## 四、环境与测量合同

- 宿主：Apple M5 Max、18 个逻辑 CPU、128 GiB 内存，Darwin 25.6.0；没有把它描述为腾讯云 4 核 4G。
- Java：Homebrew OpenJDK 21.0.11，`-Xms256m -Xmx1g -XX:+UseG1GC`。
- C++：Apple Clang 21.0.0，C++20、`-O3 -DNDEBUG -Wall -Wextra -Werror -arch x86_64`。
- **宿主是 arm64，计时 Java/C++ 都是 x86_64，经 Rosetta 执行**。原生 sanitizer 构建只用于正确性，不加入耗时比较。
- 每种负载 24,000 条指令，每语言 5 个独立进程；每进程完整预热 3 遍后创建新引擎测一次，轮换启动顺序。未证明 Java JIT 已稳态。
- 单指令延迟为 `apply()` 前后单调时钟差，计入校验、金额预检、幂等、撮合、状态更新和响应缓存；排除文本解析、文件 I/O、响应格式化、引擎构建、预热及逐步不变量扫描。
- 吞吐为指令数量除以完整测量循环时间，包含采样开销；单次区间仅毫秒级，不能充当长稳或容量测量。
- p50/p99/p99.9 采用最近秩，先按进程算再取 5 次的中位数；Max 取 5 次中的最坏值，不是把所有样本混合后再算一份分布。

## 五、真实结果

吞吐四舍五入为整数 ops/s；延迟单位为纳秒（ns），表格统计规则见上节。纳秒单位不代表纳秒测量精度。

| 负载 | 实现 | 吞吐 ops/s | p50 ns | p99 ns | p99.9 ns | 最坏 Max ns |
|---|---|---:|---:|---:|---:|---:|
| 下单/撤单混合 | Java 21 | 1,420,504 | 208 | 1,708 | 85,208 | 1,037,166 |
| 下单/撤单混合 | C++20 | 2,244,910 | 291 | 1,416 | 6,708 | 648,458 |
| 连续扫单 | Java 21 | 1,751,883 | 125 | 1,333 | 55,333 | 1,283,917 |
| 连续扫单 | C++20 | 2,358,940 | 250 | 1,334 | 3,958 | 1,013,750 |
| 重复请求密集 | Java 21 | 1,945,979 | 167 | 1,083 | 76,833 | 1,374,791 |
| 重复请求密集 | C++20 | 3,058,300 | 208 | 1,292 | 2,375 | 759,209 |

为何 p50 更低不一定吞吐更高？p50 只描述中间位置，而吞吐包含整个循环和慢请求；这里两种实现存在不同的尾部和分配行为。没有同时采集 JFR/GC 暂停、硬件计数器与逐请求关联，因此**不能把本次尾部差异确定归因于 GC、缓存或 JIT**。

## 六、CPU、内存和“还没测”的指标

`processUsage` 保存 user/system CPU，它包括解析、预热、校验、样本输出和退出，并且 Java 有辅助线程；不能把它与仅 `apply()` 的墙钟时间相除冒充热路径 CPU 利用率。

Java 在支持时读取测量线程分配字节；C++ 未做分配插桩，为 `null`。本机 RSS 查询被沙箱限制，为 `null`，不是 0，也不代表不占内存。没有 LLC miss、分支预测失败、NUMA 远端访存、context switch、page fault 或 GPU 测量数据，不能宣称这些已经改善。

GPU 不在撮合指令主路径实验内。市场风险批计算、场景模拟、离线模型等可以另设 GPU 实验，须计入批次等待、主机/设备传输与 CPU fallback；专项手册讨论的是选型边界，不是已实现加速。

## 七、如何复现与验收下一阶段

在仓库根目录运行：

```sh
bash scripts/verify-java-cpp-matching.sh
```

要求 Java 21、Node 18+、支持 C++20 和 sanitizer 的 Clang。只做正确性可追加 `--tests-only`。脚本不启动数据库、不连接生产系统，所有输出写入 `target/java-cpp-matching/`。

后续真正扩大范围必须依次过门：

1. **原生目标机实验**：相同架构、核心预算、规则与输入，对 Java 内存和 C++ 内存做充分预热、长稳和噪声披露；保留原始数据。
2. **同外壳对比**：双方使用等价网络、序列化、日志与持久确认，记录开放到达的排队和拒绝，避免把架构改造冒充语言收益。
3. **资金及恢复协议**：预占先于受理，成交/撤单按已提交序号同事务应用；未知结果不得定时释放。故障、重放、旧主、快照损坏与事件缺口全部演练。
4. **影子与迁移**：没有账务权限的 Shadow、全业务差分、以交易对为单位切换及带状态回退；不可将同一订单簿随机分流。
5. **管理决策**：比较性能预算、业务收益、人员与值班能力、三年成本；Java 已达标且迁移无净收益时停止扩大 C++。
