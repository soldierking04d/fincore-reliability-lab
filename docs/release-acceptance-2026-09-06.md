## 三、安全发布事实

1. 发布前同时校验上传包总摘要与发行目录逐文件摘要，错误制品不能进入构建。
2. 发布前生成 PostgreSQL 自定义格式备份，文件大小为 534300 字节；同时保存旧首页、旧发行信息、
   旧应用镜像和所有旁路容器基线。
3. 数据库密码和管理令牌在服务器本地随机生成，长度分别为 64 和 96 个十六进制字符；只存放在
   root 所有、权限 `0600` 的 `.env`，正文不记录真实值。
4. 应用启用 `lab,public-demo` Profile，只重建 FinCore 应用容器。Kafka、PostgreSQL、Nginx、
   Caddy、Prometheus、Grafana 以及同机其他运行容器的 ID 和启动时间均未改变。
5. 发布期间新应用尚未健康时，入口曾返回 3 次短暂 502，随后自动恢复并完成验收。因此本次是
   有备份和失败回退的单实例发布，**不是零停机或蓝绿发布**。
6. Kafka 继续使用已迁移的受管命名卷和固定镜像摘要；四个显式主题均存在，没有重建 Broker。

备份与凭据不公开。服务器内发行状态文件为 `DEPLOYED`，发布失败时的数据库恢复仍需在隔离演练中
单独证明，不能用“存在备份”替代“恢复成功”。

## 五、仍然存在的限制

- 腾讯云演示为 4 核 4 GB 单机，数据库、Kafka 和应用均为单实例，不能宣称多可用区容灾；
- 本次没有在目标机执行持续容量压测，不能根据功能验收宣称 QPS、p99/p999 或 GC SLA；
- 匿名只读和固定演示场景用于作品集展示，不替代生产 RBAC、租户隔离、WAF、审计和密钥托管；
- 镜像入口已固定到精确版本或已保存摘要，但尚未完成全量 SBOM、签名、漏洞阻断和离线供应链；
- 单实例切换存在短暂 502；若要面向真实用户，需要至少双实例、就绪探针、连接排空和可验证回滚。

后续判断当前线上版本时，应优先读取 [release.json](https://124.223.164.254/release.json)，不要引用
旧发布文档中的提交号或测试数量。
