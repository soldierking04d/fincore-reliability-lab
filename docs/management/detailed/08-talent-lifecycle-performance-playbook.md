# 人才全生命周期与绩效实战

## 一、场景：结算领域只有一个人能完成最终判断

负责人 A 熟悉 Inbox、账本、Fencing 和对账，但评审、事故和跨部门解释全部依赖 A。团队不是
立即发布一个“高级 Java 工程师”岗位，而是先完成能力缺口分析：

- C 已能完成常规开发，但缺少运行判断和授权；
- B 熟悉撮合，可以承担部分评审；
- 自动化和文档可以减少 A 的重复工作；
- 未来一年安全和灾备工作仍缺少稳定责任人。

结论可能是培养 C 成为结算备份，同时招聘具备安全与运行经验的高级工程师，而不是复制 A。

## 二、岗位评分卡

```text
岗位使命：降低资金链路人员单点并建设安全运行能力
6 个月结果：独立负责一个结算改进并通过受控接管
12 个月结果：成为安全与结算交叉领域负责人，培养下一名备份

必须证据：
- 能用数据库事务、幂等和状态机解释失败后的业务结果；
- 能根据日志、指标和数据判断问题，而不是只重启服务；
- 能说明安全、回滚和客户影响；
- 能让其他成员理解并接管方案。

可培养能力：
- 具体 Kafka 或 MyBatis 版本经验；
- FinCore 项目内部表结构；
- 当前云厂商控制台操作。
```

## 三、结构化面试

所有候选人使用相同核心维度和评分锚点：

| 维度 | 面试任务 | 强证据 | 风险信号 |
|---|---|---|---|
| 正确性 | 设计重复结算 | 先定义唯一业务效果和事务边界 | 只说加锁或加缓存 |
| 故障判断 | Kafka Lag 与 DB pending 同时上升 | 先确认瓶颈和客户影响 | 立即增加线程 |
| 安全意识 | 设计补偿接口 | 最小权限、双人复核、审计 | 只依赖隐藏 URL |
| 协作 | 产品要求周五放量 | 给数据、选项、止损和决定人 | 直接拒绝或无条件接受 |
| 组织杠杆 | 关键模块只有自己会 | 文档、演练、授权和培养 | 把不可替代当成价值 |

面试结束先独立评分再讨论，降低资深面试官对其他人的影响。

## 四、30—60—90 天入职计划

### 0—30 天：理解边界

- 完成账户、撮合、结算、同步和对账全链路演示；
- 解释三项金融不变量和生产边界；
- 跟随一次评审、发布和事故演练；
- 提交一个低风险文档或测试改进；
- 与产品、运营、测试和 SRE 建立联系人。

### 31—60 天：受控交付

- 独立完成一个有测试和监控的小改进；
- 编写 ADR 或风险说明；
- 在备份支持下完成一次发布与回滚；
- 处理一个模拟重复、乱序或积压问题；
- 获得明确反馈，不把问题留到试用期末。

### 61—90 天：证明接管

- 主持一次设计评审；
- 在负责人不提示的演练中判断问题并执行授权范围内操作；
- 向非技术角色解释客户影响和恢复证据；
- 确定未来两个季度的领域目标；
- 由负责人、伙伴和跨部门共同完成 90 天评估。

## 五、月度 1:1 模板

```text
最近最有价值的结果：
最消耗精力的工作：
一个正确判断与一个需要改进的判断：
当前角色、授权或协作阻塞：
下一项成长任务和支持者：
值班、负担和健康信号：
经理应该停止、开始、继续的动作：
```

1:1 内容保持必要隐私，行动项可以进入管理计划，但不能把个人敏感信息放进公开项目。

## 六、绩效证据示例

### 不完整结论

“C 主动性一般，重大问题仍依赖 A。”

### 可行动结论

“过去两次结算评审中，C 能识别重复消费和事务边界，但在恢复确认时等待 A 提供查询方法。下一
周期由 C 编写恢复检查并主持无提示演练；A 只观察，完成条件是 C 能独立证明账本平衡、重复效果
唯一和投影收敛。”

## 七、晋升证据

晋升不以年限或完成一个困难功能决定，应持续表现出更大范围和组织杠杆：

- 能负责一个领域的长期结果，而不是单个任务；
- 能处理模糊问题并形成可执行方向；
- 能改善他人的效率和判断；
- 能平衡客户、产品、质量、安全与成本；
- 其方法在负责人缺席时仍然有效。

## 八、低绩效改进案例

成员 D 连续三次在未确认金融不变量时提交修改。负责人先检查：任务要求是否明确、评审是否及时、
培训是否覆盖、工作量是否合理。确认支持充分后，建立四周计划：

| 周期 | 期望行为 | 支持 | 验证 |
|---|---|---|---|
| 第 1 周 | 提交前写出影响的不变量 | 领域负责人示范一次 | 评审记录 |
| 第 2 周 | 为失败路径补测试 | 测试伙伴协助 | 测试可复现缺陷 |
| 第 3 周 | 主持小型设计说明 | 提前一次预审 | 能回答回滚和监控 |
| 第 4 周 | 独立完成受控修改 | 只保留升级联系人 | 交付和反馈结论 |

如仍未达到明确标准，再按组织制度处理。公开项目不记录真实员工信息。

## 九、离职或长期缺席交接

- 列出负责系统、待决事项、风险和关键联系人；
- 指定每项接替者和最终确认人；
- 撤销账号、密钥、设备和供应商权限；
- 转移值班、告警、审批与费用责任；
- 更新文档并由接替者实际执行一次关键流程；
- 记录仍未完成的交接风险和管理决定。

## 十、团队健康月检

匿名或小范围收集五个信号：目标是否清晰、能否安全表达风险、工作负担是否可持续、是否得到
成长与反馈、跨部门阻塞是否可解决。技术负责人公布团队层面的改进行动，不追踪个人答案。

## 十一、验收标准

- 岗位从业务与能力缺口产生，而不是只补人头；
- 面试、入职、反馈、绩效和晋升使用可观察证据；
- 新成员 90 天内有真实交付和接管证明；
- 关键人负担和团队健康进入管理看板；
- 离职后接替者能够实际运行关键流程。
