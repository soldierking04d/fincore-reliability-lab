# AI 工程化落地实战

## 一、先看真实证据，而不是能力口号

FinCore 当前已经落地的 AI 能力是 Coding Agent 受控评测。它把 AI 输出当作不可信候选，而不是
直接当作正确答案。

| 证据 | 规模 | 结论 |
|---|---:|---|
| 三轮重复评测 | 3 Agent × 5 题 × 3 轮 = 45 次 | 可观察完整通过率、隐藏场景与运行波动 |
| 复杂场景首轮 | 3 Agent × 3 题 = 9 次 | 覆盖全局锁、冲突重放和在途竞态 |
| Codex 复杂场景 | 290/300，17/17 隐藏场景，0 否决 | 当前样本中端到端安全结果最好 |
| Claude 复杂场景 | 195/300，15/17，1 否决 | 强化竞态暴露原隐藏测试盲区 |
| Antigravity 复杂场景 | 175/300，10/17，1 否决 | 更快，但出现编译和安全交付失败 |

这些结果只适用于本项目的 Java、PostgreSQL 和金融可靠性任务，不构成通用模型排行榜。

## 二、现有 Coding Agent 落地链路

```text
固定缺陷提交
  → 独立候选仓库
  → 相同任务说明和公开测试
  → Agent 生成候选补丁
  → 冻结补丁、运行参数和耗时
  → 注入不可见评分器
  → 公开测试 + 隐藏场景 + 安全否决
  → 机器评分卡与人工结论
  → 只发布脱敏证据
```

关键控制包括：不让 Agent 看到答案和隐藏测试、不在候选完成后人工修补、不因编译失败缩小分母、
金融安全失败优先于总分、模型和 CLI 按实际调用记录。

## 三、用例登记卡

每个 AI 用例进入研发前必须登记：

```text
用例和业务结果：
负责人和使用者：
当前状态：提议 / 规划 / 影子 / 辅助 / 已落地 / 退出
风险等级和数据分类：
允许输入与禁止输入：
允许输出和权限：
明确禁止动作：
人工批准点：
评测集、指标和硬否决：
运行监控和成本：
降级、停止和供应商退出：
公开证据或内部审计位置：
```

仓库中的 [`ai/use-cases.json`](../../../ai/use-cases.json) 已把这些字段变成机器可读登记，并由 CI
拒绝违反资金权限硬边界的变更。

登记还包含五组不能后补的运行字段：

- `modelContext`：供应商、模型版本、提示、检索、工具策略、数据驻留、保留和训练用途；
- `valueBaseline`：当前人工流程、目标结果、单位成本上限和测量窗口；
- `releaseGate`：最低阈值、上次/下次复查和失效日期；
- `toolAccess`：允许工具、禁止范围和关闭开关责任人；
- `governance`：法务/隐私、安全评审和退出责任人。

处于 planned 的用例可以显式写“进入影子前选择”，但不能伪造已选模型或已完成评审；landed 用例
不允许保留占位值。失效日期到期会使校验失败，迫使负责人重新确认模型漂移、数据、阈值和退出条件。

## 四、用例一：事故诊断只读助手

### 输入

脱敏 Prometheus 指标、告警时间线、服务目录、批准的运行手册和本次事故记录。原始日志先做字段
白名单，不直接把完整日志送给模型。

### 输出格式

```text
已确认事实：每条附指标或事件证据
仍未知：需要什么查询才能确认
候选假设：按证据强弱排序，不写成根因
建议下一步：只提供既有手册内动作和负责人
客户影响：有证据 / 未确认
停止条件：何时关闭 AI 建议并升级人工
```

### 硬边界

模型不连接重启、扩缩容、数据库写入、Kafka Offset、云控制台或客户通知接口。事故指挥决定动作，
确定性工具执行并记录审计。

### 评测

使用历史脱敏和人工构造的反事实事故：数据库等待、Kafka 积压、GC 暂停、旧 Worker、查询投影
错误和指标冲突。测量证据引用、未知识别、危险建议、泄露、响应时间和人工采纳。

## 五、用例二：对账差异解释助手

### AI 可以做

- 对 MISSING、MISMATCH、EXTRA 证据分类并解释；
- 指出权威成交与投影的字段差异；
- 生成需要人工确认的查询与候选修复理由；
- 引用修复边界和历史已审核案例。

### AI 不能做

- 修改账本、余额、权威订单或成交；
- 自动执行投影重建或幽灵隔离；
- 把没有权威成交的投影解释成真实成交；
- 批准资金补偿或关闭审计问题。

最终操作仍调用现有确定性修复服务，由数据库锁、不变量、幂等键和授权人员控制。

## 六、用例三：客户支持摘要

模型只接收脱敏工单、业务状态字典和已批准事故更新，输出客户回复草稿。输出校验器拒绝真实账户
明细、未经批准的赔偿或 SLA、未经证实的根因和“已经完全恢复”等确定性声明。支持人员必须核对
事实后发送，所有修改用于后续评测而非直接训练。

## 七、用例四：容量与成本分析

AI 汇总 k6、Prometheus、JFR、GC、Hikari 和脱敏成本数据，输出“证据—假设—实验—保护指标”四
段式建议。例如观察数据库 pending 与 CPU，而不是看到延迟就直接建议增加虚拟线程。任何配置或
规格变更进入受控实验，AI 无权执行。

## 八、参考架构

```text
用户 / 工作流
  → 用例策略网关：身份、用例、风险和限额
  → 数据最小化：字段白名单、脱敏、检索范围
  → 模型适配层：版本、参数、超时、供应商切换
  → 输出验证：结构、引用、敏感信息和禁止动作
  → 证据存储：输入摘要、模型版本、输出和评测
  → 人工批准：显示事实、未知、成本和建议
  → 确定性业务服务：权限、不变量、幂等和审计
```

模型永远不直接获得数据库通用写权限或任意命令执行能力。工具按用例拆分，只暴露最小参数和
最小数据。

## 九、离线评测集

每个用例至少包含：

- 正常、边界、缺失数据和互相冲突的证据；
- 直接提示注入和来自日志、文档、工单的间接提示注入；
- 敏感信息诱导、越权工具请求和无限循环/无界消耗；
- 必须拒答、必须升级人工和允许给出建议的场景；
- 模型升级、提示修改、检索库变化和工具变化后的回归。

高风险用例的平均分不能抵消硬否决。一次建议修改权威资金数据、泄露敏感信息或越权执行，就应
阻止发布并进入复盘。

## 十、发布阶段

### 阶段 0：离线

使用虚构或脱敏数据，完成基线、红队攻击和成本测量。

### 阶段 1：影子

AI 与人工流程并行，输出不展示给执行者，比较质量、遗漏和延迟，避免早期自动化偏见。

### 阶段 2：辅助

向少量授权用户展示建议，所有动作人工批准；记录采纳、修改、拒绝和原因。

### 阶段 3：有界

只对低风险、可撤销动作开放参数受限工具，设置额度、双层校验、审计和自动停止。FinCore 资金
权威写入不进入该阶段。

## 十一、上线门禁

```text
[ ] 用例、负责人、业务结果和退出条件已登记
[ ] 数据分类、合法用途、保留和供应商边界已确认
[ ] 基线、攻击、拒答和硬否决评测通过
[ ] 模型、提示、检索、工具和参数可追踪
[ ] 人工批准和确定性业务校验不可绕过
[ ] 延迟、成本、限流、超时和供应商失败已验证
[ ] 原流程仍可使用，AI 可以独立关闭
[ ] 监控、值班、事故和回滚责任明确
```

## 十二、运行看板

| 类别 | 指标示例 |
|---|---|
| 价值 | 每单节省时间、事故证据汇总时间、支持首次响应 |
| 质量 | 准确率、证据覆盖、拒答、人工修改和错误确定性 |
| 安全 | 提示注入、泄露、越权工具、硬否决和异常输入 |
| 运行 | P50/P95、超时、供应商错误、Token 和缓存命中 |
| 成本 | 每次成功建议成本、每个闭环案例成本、预算偏差 |
| 人机 | 采纳、拒绝、用户信任、自动化偏见和技能退化 |

## 十三、AI 事故与降级

触发条件包括质量骤降、敏感信息输出、异常工具请求、成本失控、模型版本变化、供应商不可用或
评测过期。首要动作是关闭 AI 路径并恢复原流程，不让 AI 成为关键业务的单点。随后冻结证据、
评估影响、修复数据/提示/检索/工具边界、重新评测并由负责人决定恢复。

## 十四、影子 AI 处置

发现团队成员把真实工单、日志、源码或客户信息复制到未登记 AI 服务时，不先把问题简化为个人
违规。立即停止敏感输入、撤销暴露 Token、保存必要审计证据并评估数据影响；随后确认现有受控工具
是否无法满足效率需求，补充可用的批准路径、培训和最小权限配置。

最低团队规则：

1. 未登记供应商和个人账号不得处理内部、敏感或受限数据；
2. 浏览器扩展、IDE 插件和 Agent 工具权限也属于供应链与数据出口；
3. 模型训练使用默认不授权，保留与删除必须可解释；
4. AI 输出进入代码、客户沟通或运行操作前仍由具名人员负责；
5. 安全负责人可以关闭组织级入口，用例 Owner 负责恢复原流程。

## 十五、90 天落地计划

### 0—30 天：用例与证据

- 上线机器可读用例登记和 CI 边界；
- 整理现有 54 次 Coding Agent 证据；
- 为事故诊断和对账解释各建立 20 个脱敏场景；
- 完成数据与供应商评审。

### 31—60 天：只读影子

- 构建事故诊断和对账解释的只读原型；
- 与人工结论盲比，记录错误、拒答、延迟和成本；
- 加入提示注入、冲突证据和越权请求；
- 不接任何生产写入工具。

### 61—90 天：小范围辅助

- 仅向授权内部人员展示带引用建议；
- 记录采纳与修改，不自动执行；
- 达不到门禁则退出或继续影子；
- 通过后才评估支持摘要和容量分析。

## 十六、验收标准

- AI 用例能说明业务结果，不以调用次数代表价值；
- 已落地和规划状态由机器登记与证据区分；
- 金融权威数据、自主补偿和高风险发布存在不可绕过边界；
- 每项输出可以追溯模型、数据、提示、检索和证据；
- 发布阈值、复查、失效日期、工具权限和关闭开关均有具名责任；
- 影子 AI 有可执行的禁止、发现、上报、处置和受控替代路径；
- 评测覆盖普通质量、金融硬否决和 AI 特有攻击；
- AI 故障时原流程可以立即接管；
- 扩大权限由真实结果决定，而不是模型宣传或单次演示。
