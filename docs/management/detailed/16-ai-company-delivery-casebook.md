# 日常工作中的 AI：先把客服查资料、写回复这件事做好

当前项目优先完善[内部需求与测试](17-ai-requirements-testing-playbook.md)。本篇其他日常案例保留为补充，网站默认折叠。

> 本文是一份小范围试点方案，不是已投产案例。所有演示工单、帮助文档、版本、时间与数字均为合成样本或教学假设。
> 当前未接入真实客户、真实客服系统或真实模型。页面运行合成资料、固定候选和反馈规则；规则结果不是模型成绩。

## 1. 先选普通问题，不从“大平台”开始

客服每天都可能遇到“验证码收不到”。问题本身不复杂，但答案分散在聊天记录、旧文档、公告和不同产品版本中。
新人不知道查哪篇，熟练客服也要确认规则有没有变，客户则希望得到一条清楚、适用、不会反复折腾的说明。

AI 在这里可能有用：把已经存在的正确资料整理成适合当前问题的回复，减少找资料和改写文字的时间。
它不负责猜短信为什么没到，也不负责改变账号状态。目标是帮助客服完成一份更容易核对的草稿。

这件事不一定需要 AI。先统一资料、提供搜索和常用模板；如果这些已经解决大部分问题，就不必再增加模型成本。

## 2. 先把手工流程整理好

原流程通常是：客户描述问题 → 客服搜索几处资料 → 问同事确认 → 拼成回复 → 再修改 → 发送。
先做三个小改动：

1. 将有效帮助文档放到一个可搜索入口，过期内容不参与默认搜索。
2. 每篇标清适用产品、渠道、版本、维护人和复查日期。
3. 给最常见的问题提供可直接使用的短模板，并留下找不到答案的反馈入口。

**AI 应和“已经整理好资料的人工流程”比较，而不是把知识库治理带来的收益全算给模型。**
例如教学假设中，散乱资料时代处理一单要 10 分钟，整理后降到 8 分钟；AI 的比较基线应是 8 分钟。

## 3. 主案例：登录短信验证码一直收不到

### 客服收到什么

合成工单：

> 登录短信验证码收不到，已经点了三次。其他短信可以收到，页面还在倒计时。

客服补充的最小信息是：当前产品、验证码渠道、发生的大致时间、页面提示。
本例渠道为短信，不把邮箱验证码的处理方法混进来；不需要收集完整手机号、验证码、密码或身份证。

### 先查到哪些资料

以下文档都是教学样本，“有效”表示在本演示的知识集里可用，不代表某家公司已批准采用。

| 文档 | 适用范围与内容摘要 | 状态 |
|---|---|---|
| S1 v3《短信验证码帮助说明》 | 核对手机号与区号、检查拦截；教学规则为等待 60 秒后再试一次 | 有效 |
| S2 v2《客服升级处理说明》 | 客服记录脱敏问题与发生时间，交支持人员核查发送记录 | 有效 |

页面固定召回 S1、S2；“资料过期”会将 S1 标记过期，“找不到相关资料”返回空结果。生产接入时才需要按产品、渠道和有效版本检索，不把整个知识库发给模型。

### 草稿长什么样

 > 先请客户核对手机号与区号，并检查短信拦截设置。[S1]
> 避免连续点击；教学规则为等待 60 秒后再尝试一次。[S1]
> 仍未收到时，由客服记录脱敏问题和发生时间，交支持人员核查发送记录。[S2]

这里的 60 秒明确来自合成文档 S1，只是教学规则，不是任何真实产品规则；草稿不编造短信供应商故障或保证送达时间。
文末引用供客服快速查看原文。真实产品是否把引用同时展示给客户，应结合帮助中心体验决定。

客服只需做一次日常核对：是否答对渠道、是否和原文一致、是否有多余承诺。
可以直接采用、修改后采用，或者放弃草稿转人工处理，不设置额外的多层审批。

## 4. 一条完整的工作路线

| 阶段 | 系统或人员做什么 | 应留下什么 |
|---|---|---|
| 统一知识 | 维护人合并重复资料，标记版本和过期内容 | 有效文档清单、负责人、复查日期 |
| 检索来源 | 按问题、产品、渠道找相关有效资料 | 文档 ID、版本、匹配范围 |
| 组织草稿 | 只依据检索结果改写，不补造规则 | 简短回复与逐段引用 |
| 客服核对 | 采用、修改或转人工 | 处理选择与简短原因 |
| 记录结果 | 汇总使用和处理时间，不收集多余客户信息 | 采用率、修改点、用时、失败类别 |
| 每周改进 | 修资料和检索，补常见失败样本 | 知识变更记录、下一轮验证清单 |

问题经常出在资料和流程，而不是模型不够大。
如果十张工单都要补同一段说明，应该修知识库，而不是要求十名客服分别修改十次生成结果。

## 5. 输入与输出要小而明确

教学输入结构示例：

```json
{
  "caseId": "DEMO-SMS-001",
  "product": "Example App",
  "channel": "SMS",
  "question": "登录验证码收不到，页面仍在倒计时",
  "allowedDocumentIds": ["S1", "S2"],
  "dataMode": "SYNTHETIC",
  "modelConnected": false
}
```

预期输出只需要：

- 回复草稿、引用文档与版本。
- 找不到答案的部分，明确标为未知。
- 客服的“采用 / 修改后采用 / 转人工”选择。
- 修改原因，例如“产品版本不符”“答案太长”“新增了原文没有的承诺”。

引用 ID 必须真实存在于本次来源中；有引用也不代表每句话都正确，客服仍要核对关键规则。
后续可以记录用时和修改类别，但不把完整聊天、客户身份和验证码原样存入评测集。

## 6. 三种必须处理好的不顺利情况

### 资料过期

页面将 S1 标记过期后，会提示关键资料过期，并要求先请文档负责人更新。生产界面可提供资料维护入口。
不要为了给出完整答案而照搬旧规则；维护人修复资料之前，客服继续使用原有人工流程。

### 没有答案

如果客户询问“海外漫游下这个地区是否支持”，而知识库没有覆盖该地区，应明确说资料不足。
可以收集最小必要情况并转人工核查，但不能自造地区支持范围、运营商限制或恢复时间。

### 模型编造

若草稿额外写“每小时最多三次，明天自动恢复”，而资料没有这些规则，应拒绝该草稿。
把错误记录为“无来源的限制与承诺”，补入后续验证样本；不能因为其余两段正确就忽略这一段。

## 7. 哪些任务适合，哪些先不用

| 比较适合小试点 | 不适合直接依赖生成结果 |
|---|---|
| 重复咨询多，资料已经明确 | 资料缺失、互相矛盾或经常无人维护 |
| 主要耗时在找资料与改写 | 主要耗时在等待外部处理或确认事实 |
| 输出短，客服容易核对 | 一旦答错会造成重大后果且难以及时发现 |
| 不需要输入敏感信息 | 必须暴露完整客户身份、凭据或内部秘密 |
| 可以随时退回模板或人工 | AI 不可用就让基本工作无法继续 |

固定规则、简单搜索和模板已经满足需求时，先使用它们。
只有自然语言表达变化多、跨文档整理确实费时，而且输出可核对时，才值得继续评估模型。

## 8. 负面影响不是上线后的附录

| 可能出现的问题 | 工作中会怎样体现 | 应怎样应对 |
|---|---|---|
| 客服负担增加 | 查来源、改草稿比自己写还慢 | 记录总处理时间；关闭低价值场景，不要求强制使用 |
| 同质化或不适用回复 | 所有人都收到相同长段落，关键差异被抹平 | 按产品/渠道检索；限制长度；允许一键转人工 |
| 流畅文字造成误导 | 客服因语气肯定而忽略无来源的承诺 | 把引用放在关键段旁，验证错误案例，不以文案流畅度评分 |
| 资料维护成本被隐藏 | 文档长期不更新，生成持续复制旧答案 | 每篇有维护人；每周按失败频次修订 |
| 隐私泄露 | 把聊天、手机号或验证码复制到个人工具 | 使用最小字段和公司获准入口，不传验证码、密码等内容 |
| 上下文中的恶意指令 | 工单文字要求忽略规则或泄露资料 | 把客户文本当问题数据，不让其改变访问范围与输出限制 |
| 供应商或模型变化 | 同一资料产生不同措辞、价格与延迟变化 | 固定使用版本；变更前重跑样本；保留模板回退 |
| 成本增长 | 反复重试、输入过长、多人重复生成 | 限制上下文和尝试次数，统计每个最终采用结果的成本 |
| 原有能力退化 | 新人只复制草稿，不知道来源在哪里 | 保留知识检索入口和原文阅读，继续进行业务培训 |

没有必要为普通回复设计复杂审批。边界可以很简单：模型只组织草稿，客服核对后决定是否使用；
不自动发送，不改变账号状态，也不给模型通用系统权限。本方案未接真实模型，不宣称已经验证其安全性。

## 9. 两个同样日常的辅助例子

### 新人查内部知识库

问题：“测试环境权限从哪里申请？需要哪些信息？”
输入只包含问题和此员工实际可访问的流程文档；输出引用申请入口、必要材料和当前流程负责人。
如果流程文档过期，或者该员工无权查看某篇资料，就说明无法回答并给出正常联系路径，而不是猜流程。
业务价值看寻找正确流程所需时间和重复问同事次数；负面影响看旧资料误导与权限信息泄露。
先做一个清楚的新人索引页，再判断是否还需要 AI 问答。

### 产品需求整理与测试草案

输入是一段合成讨论：“运营希望预约活动邮件，并在发送前取消预约。”
页面使用两份合成资料：R1 已确认预约需选择未来时间并明确时区，草稿和尚未发送的预约可以取消；R2 已确认重复触发不能重复发送。
草稿不能再替产品确定未知规则：发送中能否取消、失败如何重试、变更预约截止条件都标为待确认。测试候选包括时间/时区边界、取消与发送并发、重复触发；它们不是已执行的测试。
产品负责人确认需求，研发与测试使用草稿补充工作，不让生成内容悄悄变成需求承诺。
价值看澄清轮次和漏项减少；负面影响看新增假设、同质化测试和审稿负担。

## 10. 两周小试点，不先承诺全公司推广

以下人数、样本和安排为教学假设，不是已执行记录。

| 时间 | 先做什么 | 如何决定是否继续 |
|---|---|---|
| 第 1～2 天 | 只选登录短信一个主题；整理资料和模板；确定一名知识维护人 | 资料能否说清楚当前有效规则 |
| 第 3～4 天 | 准备 40 条合成问题；记录整理后人工流程的处理时间 | 先看搜索和模板是否已足够 |
| 第 5～7 天 | 制作带引用草稿方案，覆盖正常、过期、无答案和编造 | 没有可靠来源就不生成；不填虚假的通过率 |
| 第 8～10 天 | 由两名客服角色参与模拟使用，记录采用、修改与转人工原因 | 草稿是否真的省时间，是否增加反复核对 |
| 第 11～12 天 | 修复高频问题，重跑同一批和新增问题 | 优先修知识和检索，不只改措辞 |
| 第 13～14 天 | 汇总劳动、质量、成本与使用意愿 | 保留、缩小、再试或停止，不默认扩大 |

真实模型或真实企业数据接入应在公司允许的数据与供应商范围内另行安排。
这两周的演示不能证明生产效果；真实试点应继续保留人工对照与失败样本。

## 11. 既看正收益，也把不划算算出来

### 比较什么

采用率的分母是适用工单，不是所有工单；成功率的分母是所有尝试，不只看最后留下的好草稿。
人工时间包括查来源、核对、修改、返工和失败后重新手工处理，不能只统计模型生成的几秒钟。
客户等待时间与员工主动劳动分开统计，知识整理带来的收益也单独计算。

### 教学月度假设

每月 2,000 件，其中 60% 适用；整理后人工基线为 8 分钟/件，人力成本按 100 元/小时估算。
模型与检索变动成本暂按每次 0.20 元预算，**不是任何供应商报价**；当前未调用真实模型，实际模型费用为零。
每月平台 500 元、知识维护及评测运营合计 8 小时（800 元）；初次建设 12,000 元，观察时按 12 个月分摊。
下表均为算例。“基础人工时间”包含核对、交接与登记；额外返工另算，避免遗漏和重复计费。

| 情景 | 默认教学假设 | 低采用、低可用 |
|---|---:|---:|
| 适用工单采用率 | 70% | 40% |
| 采用后有可用草稿比例 | 90% | 60% |
| 可用草稿基础人工时间 | 3 分钟检查 | 3 分钟检查 |
| 额外返工比例 × 每次时间 | 25% × 2 分钟 | 25% × 2 分钟 |
| 无可用草稿时 | 浪费 1 分钟，再按原人工 8 分钟处理 | 同左 |
| 采用工单数 | 840 | 480 |
| 平均每个采用工单人工时间 | 4.05 分钟 | 5.70 分钟 |
| 月度净释放工时 | 55.30 小时 | 18.40 小时 |
| 工时机会价值 | 5,530 元 | 1,840 元 |
| 月度变动成本 | 168 元 | 96 元 |
| 月度平台及维护成本 | 1,300 元 | 1,300 元 |
| 每月建设投入分摊 | 1,000 元 | 1,000 元 |
| 分摊建设后月度价值差 | +3,062 元 | -556 元 |

计算方式：平均人工时间 = 可用比例 ×（3 + 25% × 2）+ 不可用比例 ×（1 + 8）。
净释放工时 = 采用单数 ×（8 - 平均人工时间）÷ 60；持续成本包含调用、平台、知识维护与评测运营。
最终价值差 = 工时机会价值 - 变动成本 - 1,300 元平台维护 - 1,000 元建设分摊。

释放工时是机会价值，不等于真的减少了工资支出。没有实际减少加班、外包或形成可归因产出，就不能宣称现金回本。
如果长期落在右侧情景，停止也是合理结果；不要为了证明 AI 有用而扩大分母、隐藏返工或降低质量要求。

## 12. 最后看哪些简单指标

每周只需要一页记录：适用量、采用/修改/转人工、总处理时间、错误类别、资料修订、实际费用和人员反馈。
保留两三个代表性失败案例，说明下周究竟改哪篇资料或哪个环节，而不是展示一张不断上涨的调用量图。

模型或供应商变化、资料改版后重新验证；不可用时回到同一套模板和搜索。
先证明一个普通工作环节值得改善，再决定是否扩展到新人问答或需求整理。

关于不可信输入与生成错误，参考 [OWASP Prompt Injection](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。
此资料用于提醒风险，不代表本方案已获得认证或能消除所有错误。
