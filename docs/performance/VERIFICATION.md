## 2. 协议测试中的数据与断言

以下是**无网络替身夹具**使用的合成数据，不是数据库压测。每组 8 笔，每笔转账 10、费用 1，工具独立计算 BigInt 预期并逐账户比对接口形状的返回值：

| 场景 | 期初 | 预期终态资金分布 | 验证结果 |
| --- | --- | --- | --- |
| shared-fee | 8 付款账户各 111，收款/费用为 0，总额 888 | 付款合计 800、收款 80、公共费用 8 | 8 个成功终态；全部账户摘要匹配 |
| sharded-fee | 8 付款账户各 111，16 费用分片为 0，总额 888 | 付款合计 800、收款 80、费用分片合计 8 | 8 个成功终态；全部账户摘要匹配 |
| hot-payer | 共同付款账户 188，收款/费用为 0 | 共同付款 100、收款 80、费用分片合计 8 | 8 个成功终态；全部账户摘要匹配 |

替身中的费用选择为可预测轮转，以隔离验证工具协议；生产 FeeShardRouter 的 hash 契约由独立 Java 测试覆盖。两者不能混同为真实路由分布或真实性能。

故障输入与期望输出：

- 202 后一直 PROCESSING → INCONCLUSIVE，保留 UNKNOWN，不重发、不按成功核账。
- 接入返回 503 但原键查询 SUCCESS → VERIFIED_WITH_ACK_WARNINGS，仍仅提交一次。
- 合法账户余额比预期大 1 → FAILED_RECONCILIATION。
- 核账接口 503 → INCONCLUSIVE_RECONCILIATION，保留 unverifiedAccounts，差异数量不凭空增加。
- 原始 JSON 数字带 `0.000000000000000001` 差额 → FAILED_RECONCILIATION，不能舍入成通过。
- 源数字 `0E-18` → 精确零；不安全 Number 和本模型外非整数不能被当作精确整数。
- 准备或核账超过 60s → 停止新的网络请求；部分现场和未核账户保留。
- 开始任何写入之前已有 MANIFEST；首笔结算之前已有完整业务键清单。

金额精度与核账错误分类回归曾先复现失败，再修正解析和状态分类后全部通过。准备/核账虚拟时钟边界同时获得独立复核。

## 3. 未执行及不能推断的内容

本轮没有可用的 `docker` 命令，未启动专用 Compose、PostgreSQL 或 Kafka；没有执行真实 API 结算负载，没有修改腾讯云，没有连接钱包。运行中的公网演示未被触碰。

因此**没有本轮真实数据库 TPS、P95/P99、CPU/GC、WAL、锁等待或优化收益百分比**。未执行多实例接管、归集并发、退款回补、服务端载荷冲突修复、路由版本迁移和持续固定到达率实验。它们在各手册中有步骤与验收条件，但不能标为本轮已通过。

工具目前只核账户净额，不验证逐笔分录唯一、Outbox 最终到达或完整现货分桶；真实实验要继续执行[结算手册的逐单、逐资产 SQL 验收](settlement-performance-playbook.md)。新版候选路由与有界归集尚未实现，代码事实不能被设计图替代。
