# 三份可交给 AI 编程助手的任务单

这些是公开、合成的研发练习。先由公司批准工具与输入范围，再在开发分支中执行；不要把生产凭据、客户数据或日志原文附到任务中。任务单是协作约定，不是权限隔离工具。

## 01 / 熟悉仓库：只读定位

目标：解释 `GET /api/accounts/{id}/ledger-summary` 如何取数。

输入：`AGENTS.md`、`ai/developer-adoption/context-map.json` 以及地图指向的三份 Java 源文件。

交给助手：

> 仅阅读源码，追踪控制器、应用服务、Mapper。每个判断列文件和方法；区分事实与未知项。说明是否全量加载账本到 JVM。不要修改代码，不连接数据库，不把地图当成实时调用日志。最后给出继续确认错误响应与性能时应看的证据类型。

交付：调用链、来源引用、影响范围、未知清单。开发者逐个打开文件验证；引用不存在则退回，不把解释流畅当正确。

## 02 / 小需求：内部工单分页参数

目标：给内部工单查询生成一个可复用的参数对象，不新建 API 或数据库。

合同：

- `page` 是从零开始的 int，负数抛 `IllegalArgumentException`；不悄悄改成 0。
- `size` 是 1–200 的 int，越界抛 `IllegalArgumentException`；不悄悄截断。
- `offset` 是 long，计算前提升操作数类型；`2147483647 × 200 = 429496729400`。
- null 关键词变为空串；首尾空白按 `Character.isWhitespace` 或 `Character.isSpaceChar` 去除，内部空白保留，不改变大小写。
- 这不是 SQL 安全过滤器；真正查询必须参数绑定。深分页性能不是 long 修复解决的，应另评估游标分页。

交给助手：

> 按以上合同，在单独开发分支中实现工单分页参数处理。先看练习中的旧版与独立测试，列出边界和最小修改计划。只改练习候选文件，保留旧版与测试，不加依赖；中文注释解释输入合同、类型提升原因和限制。不要读 after 目录的参考答案。交付差异、测试命令和实际输出，不自动推送或合并。

参考答案在 `workshop/after/`；独立试用时，把 before 与 tests 复制到不含 after 的隔离工作目录，或让平台负责人制作不含参考答案的任务包。不要把可看到答案的运行称为盲测。

## 03 / 缺陷：大页码产生负偏移

复现输入：`page=2147483647, size=200`。旧版 int 乘法结果为 -200，期望为 429496729400。

交给助手：

> 先运行旧版测试，确认是断言失败而非编译/环境失败。解释 `(long) (page * size)` 为什么仍然错误。只修复必要代码，保留测试期望，再运行同一组正常、异常和极端输入用例。列出仍未验证的数据库和 HTTP 行为，按评审模板交付，不承诺生产已修复。

验收：旧版必须有正常基线通过和溢出用例失败；`overflow-only/` 只修复 P03，其他用例行为与旧版完全相同。它是 5/12 通过，不能称作完整需求已完成。`after/` 是场景 02 的完整合同实现，才要求 12/12 全部通过。环境缺失、编译失败、空用例都必须失败退出，不能当作红灯证据。
