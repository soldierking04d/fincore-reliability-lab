# AI 辅助代码改动评审记录

> 空白模板，尚未代表任何公司实际采用。记录工具版本与模型名，不记录对话中的凭据或个人数据。

## 任务与依据

- 需求 / 缺陷编号、验收合同：
- 基线提交、工具/模型版本、仓库规则版本：
- 提供的文件与脱敏输入：
- 允许修改范围、实际修改范围：
- 人确认的假设；未决项：

## 实现与测试

- 一句话根因 / 方案：
- 为什么选这个实现，哪些方案没选：
- 正常、边界、异常、回归用例：
- 旧版复现命令、退出状态、失败断言：
- 修复后命令、退出状态、报告与源码摘要：
- 未运行的测试及原因（不得留空含糊）：
- 是否改动断言、依赖、配置或接口合同，为什么：
- 性能、并发、兼容性与输入安全限制：

## 人工接手与团队反馈

- 开发者能否逐块解释修改：
- 评审人、结论、待改项：
- 回退方式（回退代码不等于自动回退数据库）：
- 找资料 / 编码 / 等待 / review / 返工用时，各自分钟数：
- 对比同难度人工任务的总用时；本次是否属于失败或放弃样本：
- 一周后发现的回归、重新打开情况：
- 值得加入共享规则的重复问题；维护负责人：

生成行数、测试数量、AI 采用率不直接等于效率。统计失败任务与评审者投入，避免把节约时间转嫁给同事。
