# Java 21 实作练习：内部工单查询分页

这是专门制作的可复现实作样例，不是本系统已发现的线上缺陷。只计算查询参数，不查询数据库、不连接网络、不访问生产，也不调用 Cursor 或任何模型。可用于公司练习 Cursor 式 AI 辅助研发，但不能把运行结果称为真实 AI 编码效果评测。

## 业务合同与兼容性

- 保留 `TicketQuery.prepare(int page, int size, String query)` 以及 `PageRequest` 的字段和类型；页号从零开始。
- `page >= 0`，`1 <= size <= 200`；非法输入现在明确抛出 `IllegalArgumentException`，不静默截断。调用方需将其转换为合适的参数提示。这是有意收紧的行为，不是完全行为兼容。
- `offset` 保持 `long` 返回类型，乘法前转为 `long`。最大合法值为 `429496729400`。这不代表生产数据库适合查询如此深的页；索引、深分页与游标方案不在本练习范围内。
- `null` 或全空白查询变为 `""`；仅去除首尾空白，内部空白和其他字符原样保留。判定严格使用 `Character.isWhitespace(codePoint) || Character.isSpaceChar(codePoint)`，包含不换行空格、窄不换行空格和全角空格；不是“删除所有不可见字符”。U+200B、U+FEFF 保留，不修改内部搜索短语。
- 常规合法分页、普通关键词、空引用和零宽字符保留行为有独立回归基线。

## 文件与练习方式

- `before/TicketQuery.java`：故意含有整型乘法溢出、参数无边界和空白处理不完整问题。
- `after/TicketQuery.java`：同接口的参考修复。
- `overflow-only/TicketQuery.java` 与 `overflow-only.patch`：只修复 int 乘法的一行补丁，不改变参数拒绝与关键词策略。保留 7 项未满足完整需求的断言失败，这不是全需求完成。
- `solution.patch`：单一修复补丁，可直接查看改动；基于旧版文件所在目录应用。
- `tests/cases.json`：12 个独立输入与字面预期，不用被测函数生成预期。
- `tests/QueryProbe.java`：只输出 Java 实际值，不含预期，不需 JUnit。
- `run-workshop.mjs`：相同用例分别编译、执行两版；检查旧版真实红且正常基线有绿、修复版全绿。

建议先只阅读业务合同、旧版和用例，让研发人员在自己的编辑器副本中提出修复，再对照补丁与测试结果复核。不要为了全绿改小测试输入、删除失败用例，或把编译失败当成证明旧代码有业务缺陷。

## 离线运行

需要本机已有 Node 24 和可运行的 JDK 21，无新依赖、无下载。macOS 自动尝试已安装的 JDK 21；其他平台默认查找 PATH。

```sh
node run-workshop.mjs
```

可显式指定 JDK 根目录，或预先配置 `WORKSHOP_JDK`：

```sh
node run-workshop.mjs --jdk "/path/to/jdk-21"
```

运行器会打印实际 JSON 报告位置。每次在系统临时目录新建独立目录，编译文件和报告都放在那里，不写入源码目录。报告包含每条输入、实际值、独立预期、通过状态和 SHA-256 源码校验值，只使用相对来源名，不保存本机绝对私有路径。

正常演示预期：旧版 4/12 通过、8/12 断言失败；修复版 12/12 通过。旧版的失败是被设计出来的练习结果，不是环境错误。运行器仅在该对照合同满足时返回成功；缺 JDK、版本不符、编译失败、Java 进程异常或探针协议错误均非零退出，并标注 `infrastructure_error`，不得算作旧版预期红。

第三个版本单独核验缺陷修复范围：5/12 通过，P03 从红变绿，其余每项实际结果必须与旧版相同。报告额外检查 `surgicalFixOnlyChangesOverflow`，不能把完整需求实现的全绿当成一行补丁的成绩。

## 公司采用时讨论什么

练习关注研发人员能否把模糊需求转为明确合同、保留正常行为、补上边界测试并审阅差异。实际收益需另外记录整理、实现、复核及返工时间；不根据这 12 个教学用例推算团队生产率。拒绝旧有非法参数以及规范化 Unicode 首尾空白都可能影响调用方，应在应用前确认。
