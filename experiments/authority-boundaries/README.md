# 第三方脚本、签名意图与资产恢复边界实验

这是 2026-10-30 Polymarket / Binance 事件的防御教学模块。事实按 `casebook.json` 的官方/研究/未知等级区分，不将研究方判断当最终根因。详细说明见 `../../docs/security/authority-boundaries-20261030.md`。

## 验证

需要 Node 24+、JDK 21+。脚本默认使用本机用户目录中的 JDK26，编译目标21；其他环境设置 `AUTHORITY_LAB_JDK`，不自动下载工具链。

```sh
node --test models.test.mjs
node verify.mjs --save
```

- `models.mjs`：8个合成回放，展示第三方脚本能力、7702授权列表语义及恢复门禁。真实哈希比较在 Node 测试中执行；浏览器 CSP/SRI/iframe 的实际阻断需另做端到端验收。
- `SigningIntentGuard.java`：真实 Ed25519 审批验签、明确域的规范编码、不可变字段绑定、防重与并发累计预算。16项断言包括伪造、篡改、过期、错误链/地址/操作、策略代次、拆单和熔断。
- `casebook.json`：事件事实、来源、业务含义、治理措施和恢复职责；作为公开说明数据，不是风控运行配置。
- `evidence.json`：`verify.mjs`真实执行生成，带测试数、用时、源码摘要和回放结果；失败不生成成功证据。

## 边界

本站静态导出已接入`requireSelfHostedScripts`发行门禁：当前无需外部脚本，生产HTML若出现外链script即中止，不因配置了SRI就自动豁免。只盘点带引号的静态引用，不检查动态加载、CSP实际效果或服务端身份。

不下载、托管或执行真实恶意脚本；不提供清空钱包合约，不生成以太坊签名，不提交交易。`signatureValid`为协议语义模型的输入桩，不能证明真实授权密码学有效。Java使用临时 Ed25519 密钥而非钱包secp256k1，不是7702交易编码器或HSM/MPC实现。

Java内的审批服务/签名服务同进程，是单元防御示例，不是独立信任域。生产要拆服务身份、发布权限和网络；内存防重与预算须替换为持久化、跨实例原子的意图和额度事务。这里的预算不是最终资金账本，签名成功也不等于广播或链上最终确认。
